# 跨设备协同套件 · 产品规格文档

> 版本：v0.2（修订稿） · 2026-11-06
> 配套：`IMPLEMENTATION_PLAN.md`（详细实施方案） · `../prototype/index.html`（高保真原型）
> 定位：**局域网内**一套键鼠控多机 + 剪贴板与真文件/目录同步
> 明确不做：公网中继、跨网传输、云端账号、屏幕镜像
>
> v0.2 相对 v0.1 的关键修正：文件剪贴板落地方式、传输加密栈、配对短码语义、差异化第三条、延迟指标口径；新增布局几何、输入所有权、跨平台文件语义、安全隐私、数据模型与工程交付。决策记录见第 12 节。

## 0. 五条产品原则

1. **局域网是硬边界**，不是缺陷。不为了“看起来完整”加公网中继。
2. **差异化是目录树 + 任务级续传 + Linux/跨生态**。文件剪贴板本身已不是空白，不能当唯一卖点。
3. **跨机文件粘贴必须先落盘**。目标机没有源机路径，远端 URI 不能凭空粘贴。
4. **配对必须两端比对**。一端显示、另一端输入，防不了中间人。
5. **剪贴板默认敏感**。密码、令牌、客户资料都可能经过它，隐私开关和排除规则属于基线能力。

### 0.1 v0.2 已定决策

| 事项 | 决策 | 理由 |
|---|---|---|
| 文件剪贴板自动拉取阈值 | **64MB**，设置范围 16–256MB | 覆盖截图、文档、小素材；大文件不阻塞剪贴板 |
| Wayland 基线 | **Ubuntu 24.04+**；22.04 只承诺 X11 | 22.04 默认 portal 可能不带 libei/EIS，不能作为基线 |
| 二维码配对 | **v1 不做**，v1.1 评估 | 需要摄像头权限，收益低于发现列表 + 手动 IP |
| 富文本范围 | v1 文本 + 安全 HTML 子集，不做 RTF | 跨平台富文本坑多，先保证文本/图片/文件 |
| 企业审计 | 仅元数据 | 内容审计会破坏端到端信任 |
| 应用层 Noise | 默认不叠 | 避免与 QUIC/TLS 双层加密和握手歧义 |

> 仍未定的只剩商业项：定价/授权、产品名、目标企业客户对审计范围的确认。

## 1. 定位与边界

### 1.1 一句话定义

在一张局域网里，把你的多台电脑（Linux / macOS / Windows）拼成一台“逻辑上的电脑”：鼠标从这块屏幕滑到那块屏幕，复制的东西在那边直接粘贴，文件夹拖过去就落地。

### 1.2 能力边界（写进产品文案，避免预期错位）

| 能力 | 支持 | 说明 |
|---|---|---|
| 键鼠跨设备 | ✅ 仅局域网 | 目标 P95 ≤12ms（capture→inject），公网不可行 |
| 剪贴板同步 | ✅ 仅局域网 | 文本 / 安全子集 HTML / 图片 / 文件引用 / 目录引用 |
| 文件与目录粘贴 | ✅ 先传输后粘贴 | 小文件自动缓存；大文件按需拉取；目录必须传完才能粘贴 |
| 文件与目录传输 | ✅ 仅局域网 | 断点续传、块级秒传、冲突策略 |
| 公网 / 跨网 / 中继 | ❌ | 定位即“同网协作” |
| 云端历史 / 账号体系 | ❌ | 数据不出网 |
| 屏幕镜像 / 扩展显示 | ❌（长期不做） | 另一个量级的产品 |

**关键修正**：v0.1 的“系统剪贴板只放文件 URI，可直接粘贴”不成立。Windows `CF_HDROP`、macOS 文件剪贴板都要求本地真实文件存在。v0.2 改为“先落盘，再上剪贴板；大文件按需拉取”，详见 4.5.4。

**判断标准**：两台设备必须能互相直连（同一网段或可路由），否则所有功能不可用。这是设计前提，不是缺陷。

### 1.3 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 个人多机开发者 | 笔记本 + 台式 + 服务器 | 一套键鼠、复制即用、大文件直传 |
| 设计/剪辑 | Mac + Windows 双机 | 素材跨机拖拽、目录结构不丢 |
| 小团队工作室 | 同一办公网多台机器 | 免 U 盘、免 IM 传文件 |
| 企业内网 | 隔离网内多机 | 数据不出网、可审计、私有化部署 |

### 2.2 空白点（我们的机会）

1. **跨平台场景下，输入 + 目录树 + 任务级续传**仍没有一款同时做好。华为多屏协同三项都有，但只在华为生态内；Flow / 通用控制跨平台，但无目录树与任务级续传。**文件剪贴板不是空白**，空白在“目录结构 + 断点续传 + Linux/跨生态”。
2. **目录是普遍缺口**。支持文件剪贴板的产品（UniClipboard / ShareMouse / Flow / 华为多屏协同）都只处理“文件”，不重建目录树；Deskflow / Input Leap 连文件都不做。
3. **断点续传普遍缺失**。开源方案基本靠整文件重传。
4. **Linux 支持是分水岭**。ShareMouse / Flow 直接不支持 Linux；Synergy 有但贵。

### 2.3 我们的差异化（三条，不多写）

- **目录是一等公民**：拖一个文件夹过去，对方按原结构重建，含空目录、相对路径、mtime；冲突可合并/重命名。
- **任务级续传**：传输任务有持久状态，断线进 `paused` 而非 `cancelled`，重连按缺失块继续；块级秒传可跨任务复用。
- **同一安装包、同一配对、同一条加密通道**：鼠标切过去的同时，剪贴板与拖拽文件复用同一条连接，不需要装两个软件、配两次对。
  （注意：不是“同一个进程”。输入通道仍独立子进程，崩溃可自动重启，见 8.1。）

## 4. 技术架构

### 4.1 分层

```
┌──────────────────────────────────────────┐
│ UI: Tauri 2 (Rust + WebView)              │
│ 托盘 / 主窗口 / 快捷面板 / 引导            │
├──────────────────────────────────────────┤
│ 应用服务层（Rust）                         │
│ 会话管理 · 屏幕布局 · 剪贴板管道 · 传输队列 │
├──────────────────────────────────────────┤
│ 核心能力                                  │
│ ┌────────┬───────────┬────────┬─────────┐│
│ │ input  │ clipboard │ files  │ discovery││
│ └────────┴───────────┴────────┴─────────┘│
├──────────────────────────────────────────┤
│ transport: QUIC (quinn) + TLS 1.3          │
│ 自签设备证书，配对后固定指纹                │
├──────────────────────────────────────────┤
│ platform shim（X11 / Wayland / macOS / Win）│
└──────────────────────────────────────────┘
```

### 4.2 技术选型

| 模块 | 选型 | 理由 |
|---|---|---|
| 语言 | Rust | 单二进制、低延迟、跨平台 |
| UI | Tauri 2 + React | 体积小，复用 Web 技术栈 |
| 传输 | quinn（QUIC）+ TLS 1.3 | 低延迟、多路复用、无需 PKI |
| 身份与加密 | 设备自签 Ed25519 证书；配对时固定证书指纹；TLS 1.3 承载 | 避免 v0.1 的 `quinn + snow` 叠加问题（QUIC 的加密层固定为 TLS，Noise 不能直接替换） |
| 发现 | mdns-sd | 纯 Rust，支持多网卡 |
| 剪贴板 | arboard + 各平台原生补充 | arboard 覆盖三平台，文件 URI 需自己补 |
| 输入捕获 | x11rb / portal+libei / CGEventTap / SetWindowsHookEx | 按平台分别实现 |
| 输入注入 | enigo（X11/Win/macOS）+ libei（Wayland） | enigo 成熟，Wayland 单列 |
| 存储 | SQLite（rusqlite） | 历史、传输状态、设备白名单 |
| 分块 | FastCDC（平均 4MB）+ blake3 | 内容寻址、天然去重 |
| 历史加密 | SQLCipher 或应用层加密；密钥放 OS Keychain / DPAPI / libsecret | 剪贴板内容可能含密码/令牌 |

> 若后续需要隐藏设备身份，可在 C2 数据通道内再叠一层 Noise，**不作为默认**，避免双层加密与握手歧义。

### 4.3 传输协议

**三条通道，按延迟敏感度分**：

| 通道 | 内容 | 要求 |
|---|---|---|
| C0 control | 心跳、状态、配对、布局同步 | JSON，1s 心跳 |
| C1 input | 鼠标/键盘事件 | QUIC DATAGRAM，单包 ≤1200B，**不可靠、不重传** |
| C2 data | 剪贴板、文件块、目录 manifest | QUIC stream，流式，带校验 |

> v0.1 的“输入通道不重传”与 QUIC stream 的可靠有序相矛盾。v0.2 明确：输入走 **DATAGRAM**；若运行的 quinn 版本未启用 datagram 扩展，降级为 stream 并接受额外延迟，M0 需验证。

**输入事件结构（20 字节）**：

```
u8  type        // 1=move 2=button 3=wheel 4=key
u8  flags       // bit0 绝对坐标, bit1 按下, bit2 相对量单位为微米(µm)
u16 code        // 按钮 / HID usage
i32 x, y        // 绝对: 归一化 0..65535；相对: 微米位移
u64 ts_us       // 本机单调时钟，仅用于本地去抖与排序
```

**关键规则**：
- 默认发**相对位移**，单位微米（µm），目标按自身 `逻辑像素/mm` 换算，保证跨 DPI 指针物理速度一致。
- 进入目标设备时发一次绝对定位，坐标在共享边重叠段内归一化，不用整屏 0..1。
- 同步 modifier 状态：切换瞬间发送当前 Ctrl/Shift/Alt/Meta 位图，避免“粘键”。
- 键盘以 **USB HID usage** 为主，目标按自身布局映射；布局不一致或特殊字符用 keysym 兜底。
- 鼠标移动合并到 250–500Hz；按键、按钮、滚轮立即发送，不合并。
- 输入 watchdog：250ms 无确认即降级提示，750ms 判定失联并自动回切。
- 各端在 C0 握手中上报：原生分辨率、逻辑分辨率、缩放、物理尺寸、旋转、`native_px_per_mm`、`logical_px_per_mm`。

### 4.4 屏幕布局与输入所有权（v0.2 新增，核心）

#### 4.4.1 坐标模型

每块屏上报以下字段：

| 字段 | 说明 |
|---|---|
| `native_w/h` | 原生像素，如 3840×2160 |
| `logical_w/h` | 系统逻辑坐标，如 1920×1080；macOS 缩放模式下不等于 native/2 |
| `scale` | 系统缩放系数；macOS 用 `native/logical` 计算有效缩放 |
| `physical_w/h_mm` | EDID 物理尺寸；缺失时用逻辑像素估算 |
| `rotation` | 0/90/180/270 |
| `origin_mm` | 在全局毫米画布中的左上角 |

推导量：

```
native_px_per_mm  = native_w / physical_w_mm
logical_px_per_mm = logical_w / physical_w_mm
effective_scale   = native_w / logical_w
ui_ppi            = logical_w / physical_w_mm * 25.4
```

**指针换算**：

```
源机相对位移 dx_mm = dx_native / source.native_px_per_mm
目标逻辑位移 dx_dst = dx_mm * target.logical_px_per_mm
```

协议里相对位移用**微米**传输（见 4.3），避免浮点漂移。**不要**用整屏 0..1 归一化做相对移动，否则小屏会突然变慢/变快。

**绝对进入**：只在共享边重叠段内归一化，映射到目标对应点；重叠段之外是死区。

**macOS 缩放模式**：13.6" 默认“看起来像 1470×956”，实际 backing 2940×1912 再下采样到 2560×1664；`CGEvent` 用逻辑点，物理尺寸用 EDID。不能假设 scale=2.0。

**X11 缩放**：`Xft.dpi=192` 只是 UI 提示，GDK 实际 scale factor 可能不同；运行时以 GDK 上报为准，缺失时回退 `Xft.dpi/96`。

- 全局布局用**毫米**建虚拟画布；布局编辑器按物理尺寸 1:1 绘制，支持适应窗口缩放。
- 网格 10mm；允许屏幕间留空隙（死区），不允许重叠；重叠时给出警告并拒绝保存。
- 每块屏独立参与边缘配对；输入所有权按**设备**而不是按屏，进入某设备的任一块屏即由该设备接管。

#### 4.4.2 边缘配对算法

1. 为每块屏生成四条边线段，长度用 mm。
2. 两条边“相对且靠近”（间距 ≤20mm）且**投影重叠 ≥25%** 时，配为一对。
3. 只有重叠段可穿越；重叠段外是死区，光标停在边界。
4. 穿越点按重叠段比例映射，避免从 4K 底部穿到小屏顶部时跳变。
5. 角点归属：优先匹配投影内包含该点的边；仍歧义时**水平边优先**（可配置）。
6. 共享边覆盖率 = `overlap_mm / 源设备该边长度`（水平共享边用屏高，垂直共享边用屏宽）；UI 明确显示百分比。
7. 布局变更后重新计算所有边对，并做一次往返自测（A→B→A 落点误差 ≤2 逻辑 px）。

#### 4.4.3 输入所有权状态机

```
LOCAL_OWNED ──边缘穿越──▶ HANDOFF_OUT ──▶ REMOTE_OWNED
     ▲                                        │
     └──── 回切/失联/锁屏/权限丢失 ────────────┘
```

| 事件 | 行为 |
|---|---|
| 光标穿越共享边 | 源机隐藏并锁定光标，目标机在映射位置出现光标；发送 modifier 位图 |
| 回切快捷键 | 默认 `Ctrl+Alt+Home` 拉回本机；可选方向键版本，避免与左右切换语义混淆 |
| 目标机本地输入 | 默认“本机优先”：目标机物理鼠标/键盘一动，立即把所有权交还目标机，避免抢鼠标 |
| 目标机锁屏/休眠 | 立即 `SUSPENDED`，释放所有按键/按钮，所有权回本机，托盘提示 |
| 全屏应用/游戏 | 默认禁止穿越（可加白名单），避免误切 |
| 拖拽中到达边缘 | 按住鼠标时**不穿越**；若是文件拖拽，悬停 300ms 后触发传输，而不是切换输入 |
| 目标机断网/崩溃 | 750ms 内回切本机，提示“目标不可达”，后台重连 |
| 权限被撤销 | 输入能力灰置，立即回切；剪贴板与文件仍可用 |
| 三台以上链式 | A→B→C 逐级转移；每台只记录“上一个所有者”，回切按栈返回 |

**按键卫生**：每次交接发送“当前按下的 modifier 位图 + 已按下按钮列表”；回切时目标端释放所有键，避免 Ctrl 卡住。

#### 4.4.4 实测分辨率适配（本机 4K + MacBook Air M4）

**本机实测（Linux X11）**：`xrandr` 当前 `HDMI-0 3840×2160@60Hz`，物理尺寸 `631×360mm`（约 28.6"），约 154 PPI；`Xft.dpi=192`，按 2.0× 估算逻辑分辨率 `1920×1080`（约 77 逻辑 PPI）。实际 GDK scale factor 以运行时为准。

**MacBook Air M4 32GB**：32GB 是内存配置，不影响分辨率。M4 Air 有两种屏幕，程序会自动读取实际型号/模式：

| 机型 | 原生分辨率 | 默认逻辑分辨率 | 有效缩放 | 物理尺寸 | 面板 PPI | 逻辑 PPI |
|---|---|---|---|---|---|---|
| MacBook Air M4 13.6" | 2560×1664 | 1470×956 | 1.741× | 293×183mm | 224 | ≈128 |
| MacBook Air M4 15.3" | 2880×1864 | 1710×1107 | 1.684× | 330×206mm | 224 | ≈132 |

**与本机 4K 的适配结果**：

| 指标 | 13.6" Air | 15.3" Air |
|---|---|---|
| 屏幕宽度比（本机/Air） | 631/293 = **2.15×** | 631/330 = **1.91×** |
| 共享边覆盖率（Air 高/本机高） | 183/360 = **50.8%** | 206/360 = **57.2%** |
| 逻辑像素速度倍率（Air px / 本机 px） | 5.02/3.04 = **1.65×** | 5.18/3.04 = **1.70×** |
| 指针物理速度 | **1:1（mm/s 归一化）** | **1:1** |

**结论**：
- 4K 屏比 Air 宽约 2 倍；并排时必须按物理尺寸画，不能把两块屏画成同样大小。
- Air 只能覆盖本机 50.8% / 57.2% 的右边缘，其余是死区；布局编辑器要把有效共享段高亮出来。
- 用整屏 0..1 映射会让 Air 上的指针速度变慢 1.65×；必须用微米/毫米换算。
- 推荐 Air 垂直居中放置；如果桌面高度不同，用布局编辑器拖动，直到共享段覆盖你常用的中间区域。
- 两端关闭“鼠标加速/指针加速”，否则物理速度归一化会被系统加速曲线破坏。
- 若 Air 改用“更多空间”缩放（如 1710×1107），逻辑 PPI 与倍率会变化；程序读取实际模式后自动重算，不需要手工配置。

### 4.5 文件与目录传输

**目录 manifest**：

```json
{
  "v": 1,
  "root_name": "project",
  "total_bytes": 1610612736,
  "entries": [
    {"rel": "",            "type": "dir",  "mode": 493, "mtime": 1730000000},
    {"rel": "src",         "type": "dir",  "mode": 493},
    {"rel": "src/main.rs", "type": "file", "size": 8123, "blake3": "..."},
    {"rel": "empty",       "type": "dir",  "mode": 493}
  ]
}
```

**传输状态机**：

```
queued → transferring → (网络中断) → paused → transferring → completed
                     ↘ cancelled（用户主动）
                     ↘ failed（重试 3 次后）
```

**落盘策略**：
1. 临时目录 `<dest>/.cdsync-tmp/<task_id>/`，**必须与目标目录同一文件系统**；否则原子 rename 会报 `EXDEV`。空间不足时在同盘兄弟目录建临时区。
2. 大文件预分配稀疏文件，或按块写 `part` 文件；SQLite 记录每块 `(task_id, rel, offset, len, blake3, state)`。
3. 单文件全部块校验通过 → 单文件原子 rename；整目录传完后按 manifest 重建空目录并移入，**不能假设整目录 rename 原子**。
4. 断线恢复：读 SQLite 任务记录，比对已落盘块索引，只补缺失块；源端块缓存按 blake3 复用。

**冲突策略（F-23）**：目标已存在同名文件/目录时，默认“询问”，可选覆盖 / 跳过 / 重命名（`name (1).ext`）/ 合并目录；支持“本次全部应用”。

**块缓存**：全局内容寻址库，默认上限 8GB，且不超过磁盘剩余空间的 10%，LRU 清理；跨任务复用。缓存文件权限 0700，退出不删除（受配额约束）。

#### 4.5.4 剪贴板中的文件与目录（关键修正）

| 内容 | 策略 |
|---|---|
| 文本 / 图片 ≤8MB | 直接走 C2，内联到剪贴板 |
| 文件 ≤64MB（可配） | 自动拉取到本机缓存，再写入系统剪贴板（`CF_HDROP` / `NSFilenamesPboardType`），粘贴立即可用 |
| 文件 >64MB | 剪贴板只显示“文件引用”，粘贴时提示“正在接收”，完成后自动置入剪贴板；或用户点“接收并粘贴” |
| 目录（任意大小） | **必须先完整传输**，再写入剪贴板；不支持“只放目录 URI” |
| 平台 promise | 能用的平台用 promise 做延迟物化；不能用时退回显式“接收后粘贴” |

**文案必须诚实**：不能写“文件 URI 可直接粘贴”。改为“小文件复制后即可粘贴；大文件首次粘贴会自动接收”。

### 4.6 跨平台文件语义（v0.2 新增）

目录是差异化，文件名/路径兼容不做好会直接翻车。

| 问题 | 策略 |
|---|---|
| Windows 非法字符 `<>:"/\|?*` 与控制字符 | 写入时替换为 `_`；manifest 保留 `orig_name` 用于显示；冲突加短哈希后缀 |
| Windows 保留名（CON/PRN/AUX/NUL/COM1…） | 前缀 `_` |
| Windows 260 字符路径 | 默认启用 long path；超限时截断并加哈希，UI 提示 |
| macOS NFD vs NFC | manifest 统一 NFC；写入前归一化，避免“同名不同码” |
| 大小写不敏感文件系统冲突 | 检测 casefold 冲突，自动重命名 `~2` 并提示 |
| 同名文件/目录已存在 | 走 4.5 冲突策略，默认询问 |
| 符号链接 | 默认不跟随、不创建；manifest 标记并跳过，汇总提示 |
| 硬链接 | 当作独立文件传输，块级去重 |
| xattr / ADS / resource fork | v1 不保留，文档写明 |
| 稀疏文件 | 不保留稀疏结构，按逻辑内容传输 |
| Unix 权限位 | 能保留则保留；Windows/macOS 做 best-effort 映射，不迁移 ACL |
| mtime | 保留，统一 UTC |
| 磁盘空间 | 传前预检总量 + 5% 余量；不足直接失败并提示 |
| FAT32 单文件 4GB 限制 | 预检目标文件系统，超限拒绝并给出可操作提示 |
| 空目录 | 必须创建 |
| 10 万文件大目录 | manifest 流式生成、分批传输，UI 先显示总数 |

### 4.7 剪贴板管道

```
本地剪贴板变化(序列号/AXFIXES/changeCount)
  → 快照(类型+内容+来源设备+内容哈希+文件/目录 manifest)
  → 防回环(origin_id + hash + seq，忽略同源回声)
  → 加密 → 推送 C2
  → 对端落盘 → 设置系统剪贴板 → 抑制该次回传
```

- **防回环**不再依赖固定 2s 窗口，改为 `origin_id + content_hash + seq`；慢速大图也不会 ping-pong。
- **类型范围**：`text/plain`、安全子集 `text/html`（去脚本/外链）、`image/png`、`image/jpeg`、文件列表、目录 manifest。RTF 放 v1.1，先不承诺。
- **敏感应用排除（F-21）**：检测前台应用 bundle id / 进程名，命中密码管理器（1Password、Bitwarden、KeePassXC 等）时跳过同步并提示；支持“隐私模式” 5/15/30 分钟，托盘可一键暂停。
- **历史存储**：SQLite + 密钥放 OS Keychain/DPAPI/libsecret；默认保留 30 天；支持清空、固定、按设备筛选。
- **大内容**：图片/文本 >8MB 只存预览与哈希，内容按需拉取，不把 1.5GB 目录塞进剪贴板历史。

### 4.8 配对与安全

1. 双方通过 mDNS 发现，交换设备自签证书（含公钥）。
2. **SAS 短码**：`code = blake3(sorted(pubA, pubB) || nonce)` 取 6 位（nonce 由发起方生成并随握手发送，双方使用同一个），**两端同时显示同一个码**，两端都点确认；60s 过期，可重新生成。
   （v0.1 的“一端显示、另一端输入”防不了中间人，废弃。）
3. 配对成功写入白名单：`device_id + 证书指纹 + 名称 + 能力位`。
4. 后续连接走 TLS 1.3 + 证书指纹固定；指纹不匹配直接拒绝，不弹“是否继续”。
5. **能力位（F-22）**：输入 / 剪贴板 / 文件传输，按设备单独开关；剪贴板内部再按文本、图片、文件、目录细分。默认全开，可随时收回。
6. 输入注入额外开关：默认“已配对设备可控制”，可选“每次需本机确认”。
7. **撤销配对**：删除密钥与缓存、断开连接、清除该设备来源的剪贴板条目。
8. **可被发现（F-24）**：默认开启 15 分钟，之后转隐身；企业可配置默认关闭，仅手动 IP（扫码 v1.1）。
9. **企业审计（P3）**：只记录元数据（设备、文件名、大小、哈希前缀、时间、结果），不记录内容；E2E 加密不因此破例。
10. **威胁模型**：局域网窃听、MITM、被攻陷的已配对设备、剪贴板敏感数据泄露。不覆盖：已攻陷的操作系统、物理接触、恶意提权驱动。

| `devices` | id, name, cert_fingerprint, pubkey, capabilities, paired_at, last_seen |

### 4.10 协议版本与错误码

- `protocol_version = major.minor`，C0 首包协商；major 不兼容直接拒绝并提示升级；minor 用 feature bits 降级。
- 错误码统一为 `E_*`，UI 显示“人话 + 下一步动作”，日志保留原始码：

| 码 | 场景 | 用户提示 | 动作 |
|---|---|---|---|
| `E_DISCOVERY_NO_PEER` | 发现不到设备 | 检查同网段/AP 隔离 | 手动 IP（扫码 v1.1） |
| `E_PAIR_CODE_MISMATCH` | 短码不一致 | 可能被中间人，停止配对 | 重新生成、检查网络 |
| `E_AUTH_KEY_MISMATCH` | 指纹不匹配 | 设备身份已变化 | 撤销后重新配对 |
| `E_PERM_DENIED` | 权限缺失 | 输入不可用，剪贴板仍可用 | 打开权限向导 |
| `E_NET_UNREACHABLE` | 目标不可达 | 已回切本机 | 后台重连 |
| `E_DISK_FULL` | 空间不足 | 需要 X GB | 更换目录/清理 |
| `E_FS_UNSUPPORTED` | 文件系统不支持 | 例如 FAT32 4GB 限制 | 更换目标盘 |
| `E_CONFLICT` | 同名冲突 | 选择覆盖/跳过/重命名 | 应用全部 |
| `E_PROTO_VERSION` | 版本不兼容 | 请升级到 X | 打开下载页 |

### 5.3 交互规则

| 场景 | 行为 |
|---|---|
| 光标碰共享边 | 停留 80ms 判定，避免误触；继续移动则穿越 |
| 穿越瞬间 | 源机光标隐藏并锁定；目标机光标出现在按几何映射的位置 |
| 回切 | 默认 `Ctrl+Alt+Home`；可选方向键版本 |
| 目标机本地输入 | 本机输入优先，立即交还所有权（可配置） |
| 目标机离线/休眠/锁屏 | 不穿越；已穿越则 750ms 内回切，提示“目标不可达” |
| 权限未授予 | 输入功能灰置，点击弹权限向导；剪贴板/文件仍可用 |
| 拖拽中越界 | 普通拖拽不切换；文件拖拽悬停 300ms 触发传输 |
| 剪贴板冲突 | 以内容哈希为准；同源回声直接丢弃；不同源同内容 500ms 内合并 |
| 大文件粘贴 | 显示“正在接收 X%”，完成后自动置入剪贴板 |
| 同名冲突 | 弹窗选择覆盖/跳过/重命名/合并，可“全部应用” |

### 5.4 状态与反馈矩阵（v0.2 新增）

| 页面 | 空状态 | 加载/进行中 | 错误 | 权限受限 |
|---|---|---|---|---|

## 8. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| Wayland 抓输入需 portal 授权，可能每次会话弹窗 | 体验差 | M0 先验证；限定发行版；必要时降级“仅注入、不捕获” |
| Ubuntu 22.04 默认 portal 不带 libei/EIS | Wayland 不可用 | 明确最低发行版，22.04 只保证 X11 |
| macOS 15 新增“本地网络”权限 | 发现失败 | 权限向导 + 拒绝后的手动 IP 兜底 |
| macOS 未公证被 Gatekeeper 拦截 | 无法安装 | Developer ID 签名 + 公证；或引导右键打开 |
| macOS Secure Input（密码框）阻断事件监听 | 输入失效 | 检测并提示；密码框场景不承诺 |
| Windows 防火墙默认拦截入站 | 发现/连接失败 | 安装时添加规则；失败时引导手动放行 |
| Windows UIPI：无法注入提权窗口 | 部分场景失效 | 文档说明，不做驱动级绕过 |
| 键盘布局不一致（US/DE/中文） | 字符错乱 | HID usage + keysym 兜底；设置里可切换映射 |
| IME 组合输入被打断 | 中文输入异常 | 组合期间不切换设备；交接时清空组合态 |
| 拖拽中越界打断拖拽 | 体验差 | 按住按钮时禁止穿越；文件拖拽单独触发传输 |
| 企业网 AP 隔离 / 组播封锁 | 发现失败 | 手动 IP + 扫码兜底，文案明确提示 |
| 多网卡/VPN 选路错误 | 连不上 | 候选地址探测，逐个试连 |
| 输入与文件共用进程崩溃 | 全部中断 | 输入通道独立子进程，崩溃自动重启（与“同一通道”不冲突） |
| 临时目录与目标不同文件系统 | rename `EXDEV` | 临时目录必须同盘；否则改为复制 + 校验 + 删除 |
| 目录 rename 非原子 | 部分可见 | 单文件原子 rename，目录最后移入；失败可恢复 |
| 目录权限/符号链接 | 越权写盘 | manifest 拒绝绝对路径与 `..`，符号链接默认不跟随 |
| 大目录（10 万文件）manifest 过大 | 卡顿 | 流式生成 manifest，分批传 |
| 块缓存无限增长 | 占满磁盘 | 配额 + LRU + 占用可见 |
| 杀毒软件误报钩子 | 安装/运行受阻 | 代码签名；提交白名单；企业部署文档 |
| 协议版本漂移 | 新旧设备连不上 | C0 协商 + feature bits + 明确升级提示 |
| 二维码需要摄像头权限 | 流程复杂 | 放 v1.1，v1 用发现列表 + 手动 IP |
| 产品名 CrossEdge 商标冲突 | 上线风险 | 发布前做商标检索 |

## 12. 决策记录

### 12.1 已决策（v0.2 定稿）

1. **文件剪贴板阈值**：默认 64MB，可配 16–256MB；大文件粘贴时按需接收。
2. **富文本范围**：v1 纯文本 + 安全 HTML 子集；RTF 不做。
3. **Wayland 基线**：Ubuntu 24.04+；22.04 只承诺 X11。
4. **二维码**：v1 不做，v1.1 再评估；v1 用发现列表 + 手动 IP。
5. **企业审计**：仅元数据，不碰内容。
6. **应用层 Noise**：默认不叠；企业要求再加选项。
7. **指针映射**：物理 mm/s 归一化，协议传输微米；禁止整屏 0..1 相对映射。
8. **布局绘制**：按物理尺寸 1:1，支持适应窗口缩放；共享边只高亮重叠段。

### 12.2 仍待业务确认

1. **定价/授权**：个人买断 + 企业按席位？离线激活怎么做？
2. **企业审计范围**：只记元数据是否满足目标客户，需要客户书面确认。
3. **产品名**：CrossEdge 需商标检索后再定。
4. **Air 尺寸**：用户实际是 13.6" 还是 15.3"，装好后程序自动读取；原型两种都可切换。
